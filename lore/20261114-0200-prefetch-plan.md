# Plan: Job prefetch (lookahead) in the Dispatcher, with dynamic scaling

## Context
Today the dispatcher reserves at most one job per **idle** thread, so after a job finishes the thread sits idle until the next poll's round trip completes. With prefetch, each thread also holds up to `prefetch` **queued** jobs waiting behind the one it runs. A thread that finishes a job pops the next one from its own queue at once, and the dispatcher refills the queue in the background. `prefetch_dynamic` scales the queue depth with demand, so a nearly empty queue isn't spread across threads (where jobs would wait behind long jobs instead of going to idle threads elsewhere).

Semantics of `prefetch` (the number of queued jobs per thread, beyond the running one):
- `0` (default): fetch only for idle threads, one job each. Exactly today's behaviour and lock names.
- `1`: up to 1 queued job per thread. An idle thread gets 2 (one runs, one waits); a busy thread with an empty queue gets 1.
- `N`: up to N queued jobs per thread, i.e. up to N+1 held.

Repo: `/mnt/c/workspace/delayed_job-multi-threaded`, branch `multi-threaded`. delayed_job_mongoid needs no change: its sorted batch reserve works per lock name.

## Key decisions
- **Per-worker queues:** each worker keeps its own inbox (the existing `@inboxes` map in the dispatcher), now holding up to `prefetch + 1` jobs. Rejected alternative: one queue shared by all threads. A thread would then run jobs locked under another thread's name, and the ClearLocks plugin could unlock a job another thread is still running.
- **Lock names (slots):** with prefetch ≥ 1, each worker gets `prefetch + 1` fixed slots named `"#{worker.name} slot:#{j}"` (j = 0…prefetch). With prefetch 0 there are no slots: the worker locks under its plain `worker.name`, as today.
  - A slot holds at most one job, queued or running, and the job keeps its slot's lock name until it finishes or is released. Only free slots are reserved into, so names are never shared.
  - Distinct names are required because `reserve` for a name also returns jobs already locked under that name (crash recovery).
  - No cursor: the dispatcher tracks which slots are held (`@slot_jobs`). Run order comes from the FIFO inbox, not slot numbers.
  - Each slot is a `Worker.named(slot_name)` object, a real Worker instance that doesn't reset the lifecycle. Any backend's `reserve_batch` already accepts these.
  - With prefetch ≥ 1, no job is locked under the plain `worker.name`, so ClearLocks does nothing there. The dispatcher clears the slot names itself (see Shutdown).
- **Trade-off, documented:** a queued job waits behind its thread's current job. Prefetch suits many short jobs; `prefetch_dynamic` limits the cost when the queue is thin.

## Changes

### 1. Settings — `lib/delayed/worker.rb`
- `cattr_accessor :prefetch` (`DEFAULT_PREFETCH = 0`) and `:prefetch_dynamic` (default false). Both are reset in `Worker.reset` and added to `#initialize`'s option list.
- `Worker.validate_prefetch!`: prefetch must be an integer ≥ 0, otherwise ArgumentError.
- `Worker.slot_name(name, j)`.
- `Worker.lock_names(prefix, pid, threads, prefetch = 0)` lists the slot names when prefetch ≥ 1, and the plain names otherwise.

### 2. Dispatcher — `lib/delayed/dispatcher.rb`
- **State:**
  - `@slots[worker]`: the worker's slots, built once in `initialize` on the main thread.
  - `@slot_jobs[slot] = job`: the held slots.
  - `@slot_owner[slot] = worker`.
  - `@running_slot[worker]`.
  - `@depth`: the current queue depth.
  
  `@idle` is replaced by "free slots".
- **Queue depth (`@depth`, 0…prefetch):** a worker may hold at most `@depth + 1` jobs (running + queued). A poll requests `@depth + 1 - held` of the worker's free slots, whichever slots they are: slots rotate, so a slot's index says nothing about whether its job runs or waits.
  - Without `prefetch_dynamic`, `@depth = prefetch` always.
  - With `prefetch_dynamic`, `@depth` starts at 0 and, after each poll that requested at least one slot:
    - **full hit** (reserved == requested): `@depth = min(@depth + 1, prefetch)`;
    - **partial hit** (reserved < requested, so the queue ran dry): `@depth = 0`, so the next round fetches only for idle threads.
    - Polls that requested nothing leave `@depth` unchanged.
  - Jobs already queued in slots above a lowered depth stay queued; they just aren't refilled.
  - "Partial hit" reads the request's "less than the number of workers" as fewer jobs reserved than slots requested in that round.
- **Free-slot order (`snapshot`):** rounds by held count. First one free slot of every idle worker (held 0), then one more slot for every worker now holding 1, and so on, up to `@depth + 1` held each. The highest-priority jobs therefore go to threads that start them at once. Base `reserve_batch` stops at the first empty reserve, so lower slots never starve higher ones.
- **`poll(free_slots)`:** `reserve_batch(free_slots, …)` returns `[[slot, job]]`. `dispatch(slot, job)` records the slot as held, increments `@in_flight`, and pushes `[slot, job]` to the owner's inbox.
- **No waiting while free slots remain:** `poll_loop` only waits (`wait_before_next_poll`) when no free slot is left within `@depth`, or the queue ran dry. After a full hit raises `@depth`, the newly allowed slots are free at once, so it polls again without waiting.
- **Continuous refill:** when a job finishes, its slot is freed and an event signalled. The dispatcher wakes and refills every free slot in one `reserve_batch`; a queue is never drained before it is refilled.
- **Worker thread (`work`):** pops `[slot, job]`.
  - After `stop?` or past the shutdown deadline: `release_unstarted(slot, job)`.
  - Otherwise: set `@running_slot[worker] = slot` and run the job.
  
  `job_finished` and `release_unstarted` free the slot and signal the event.
- **Accounting:**
  - `in_flight` counts queued and running jobs, so `exit_on_complete` waits for queued ones too.
  - "Queue dry" means fewer jobs were reserved than there were free slots; `repoll_after?` uses the same comparison.
- **Lock heartbeat:** `heartbeat_names` = the names of every held slot, minus an overrun job's slot (looked up via `@running_slot`). Queued jobs' locks are refreshed too.
- **Releasing:** `release_unstarted` and `release_interrupted` call `clear_locks!(slot.name)`, and `locks_released` reports the slot names.
- **Shutdown (`stop_threads`), with prefetch ≥ 1 only (prefetch 0 keeps today's behaviour: a job already handed to a thread still runs):**
  1. Drain every inbox without blocking (`pop(true)` until empty).
  2. Release each drained job by its slot (unlocked, attempts unchanged) and publish one `locks_released` event (`reason: 'shutdown'`).
  3. Push `STOP`; the existing graceful, interrupt and quit logic follows.
  
  Inboxes of crashed threads are drained the same way. As each worker thread exits, the dispatcher also runs `clear_locks!` on that worker's slot names, unless a stuck job still holds one.
- **`procline` / instrumentation:**
  - procline, e.g. `3/4 busy, 2 queued, depth 1/2, queues=*`.
  - `reserve` payload: `:requested` is the number of free slots; add `:depth`.
  - `process_payload` gains `:prefetch` and `:prefetch_dynamic`.
- **Unchanged:** `work_off` (synchronous, one job at a time). It reserves under the worker's plain name, so the heartbeat refreshes that name in this mode (`heartbeat_names` falls back to the workers' names when no slot is held).

## Tests (new `spec/prefetch_spec.rb`, plus updates)
- Prefetch 0 is unchanged: same lock names, and the existing suite stays green.
- Prefetch 1, 2 threads, slow jobs: 4 jobs locked at once under 4 distinct `slot:N` names. The next job starts with no reserve in between.
- Prefetch 2: an idle worker gets 3, and a busy worker with an empty queue gets 2 (then 1 as its queue refills). Highest-priority jobs go to idle threads' slot 0.
- A busy worker's running or queued job is never re-reserved.
- Dynamic scaling, through the `:depth` payload and the slots requested:
  - depth starts at 0;
  - the poll after a depth increase happens at once (no wait);
  - it rises by one per full hit, up to prefetch;
  - a partial hit drops it to 0;
  - an empty request leaves it unchanged;
  - queued jobs above a lowered depth still run.
- Shutdown:
  - prefetch 0: a job handed to a thread just before TERM still runs (unchanged behaviour);
  - TERM: queued jobs are released (unlocked, attempts 0), running jobs finish, `locks_released` is published;
  - quit and the shutdown timeout behave the same;
  - the real-signal spec on CRuby: TERM while jobs are queued.
- `exit_on_complete`: 50 jobs, 4 threads, prefetch 2, dynamic on and off: each job runs exactly once.
- Heartbeat touches queued slots' names and skips an overrun slot.
- Launcher: `lock_names` includes the slot names; a SIGKILLed child's queued jobs are recovered. Command, rake and validation parsing.
- Mongoid: its suite against the branch, plus one dispatcher spec with prefetch 1 and dynamic scaling that runs every job exactly once.
